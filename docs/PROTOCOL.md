# Protocol

Sections 1-5 describe what was run, written up after the runs from the code and logs. Section 6 states what was decided after seeing results. Section 7 fixes the rules for the next experiments before they are run.

## 1. Research question

Can a sequence model route information using simulated chromatin loop extrusion, with no positional encoding and no query-key products, and does that mechanism help when the data follow extrusion-like rules?

Hypotheses:

- **H1 (length).** Extrusion keeps its accuracy on sequences up to 8x longer than any training sequence.
- **H2 (data).** With few training sequences, extrusion beats generic mixers given the same backbone.
- **H3 (mechanism).** The two-arm, load-anywhere form matters: with one layer, it beats the one-arm ablation.
- **H4 (interpretability).** Learned stall probabilities reflect barrier orientation without being told about it.

## 2. Task

Tokens and sampling probabilities: `.` 0.63, `E1`/`E2`/`E3` 0.02 each, `P` 0.07, `>` 0.12, `<` 0.12. These probabilities were tuned before any model was trained, using only the label distribution: the goal was no class above about 45% at any test length.

Label at each promoter: strength of the strongest enhancer it can reach, 0-3. Insulated iff a `>` precedes a `<` strictly between promoter and enhancer. All other positions are ignored in the loss and metrics. `tests/test_models.py` checks the scanning implementation against a direct O(n^3) statement of the rule.

Splits, all generated by seed:

| Split | Seed | Sequences | Lengths |
|---|---|---|---|
| train | 1 | 4000 (or the first 300 drawn with that seed) | 24, 32, 40, 48, 56, 64 |
| validation | 2 | 600 | 24-64 |
| test 64 / 128 / 256 / 512 | 3 / 4 / 5 / 6 | 300 / 300 / 200 / 100 | fixed |

Batches are drawn from one length bucket at a time, so no padding is needed.

## 3. Models

Shared backbone: token embedding (width 64), then per layer: residual width-5 convolution, residual long-range mixer, residual MLP (64 -> 128 -> 64), pre-LayerNorm. Linear head to 4 classes. Only the mixer differs:

| Mixer | Definition |
|---|---|
| `extrusion` | two-arm extrusion contacts, 4 motor types (see `DERIVATION.md`) |
| `one_arm` | arms start at the query, same parameterization |
| `attn_rope` | 4-head bidirectional softmax attention, rotary positions |
| `attn_alibi` | 4-head bidirectional softmax attention, ALiBi slopes `2^(-8h/4)` for heads h = 1..4 |
| `bilstm` | bidirectional LSTM, 32 units per direction |

Parameter counts at 3 layers: extrusion and one_arm 141,428; attention 163,268; BiLSTM 188,612.

## 4. Training and selection

AdamW, learning rate 2e-3, weight decay 0.01, 100-step warmup then cosine decay, batch 32, gradient clipping at 1.0, 3000 steps, 2 CPU threads. Validation accuracy every 250 steps; the best validation checkpoint is kept. Test splits are never used for training or selection.

## 5. Runs

36 runs, every one recorded in `results/runs.jsonl`:

| Setting | Mixers | Seeds |
|---|---|---|
| 4000 sequences, 3 layers | all five | 0, 1, 2 |
| 4000 sequences, 1 layer | extrusion, one_arm | 0, 1, 2 |
| 300 sequences, 3 layers | all five | 0, 1, 2 |

Metric: accuracy over promoter positions at each test length. Seeds are reported as mean and min-max; 3 seeds do not support significance tests.

## 6. Decisions made after seeing results

- **The 1-layer and 300-sequence settings were added after the 4000-sequence, 3-layer grid saturated.** Extrusion, one_arm and BiLSTM were all at 99.7% or above there, so that grid could not test H2 or H3. Both follow-up settings were chosen before any of their runs started, and all their runs are reported.
- **The released checkpoint was retrained.** `results/extrusion_seed0.pt` came from a separate training of extrusion seed 0 for the motor inspection (`inspect_learned.py`, 4 CPU threads), with identical data, schedule and selection. A different thread count changes floating-point summation order, so its test accuracy (`results/replay.json`) differs from the seed-0 row of the grid in the third decimal.
- **H4 was checked on that one checkpoint only.** Other seeds' motors were not inspected.

## 7. Fixed before the next experiments

The next experiments are listed in the README. These rules hold for all of them:

1. Same backbone and matched parameter counts (within 20%) across mixers. Selection uses validation data only.
2. At least 3 seeds per setting. Report every run, including failures.
3. **Stop rule.** If extrusion does not beat both attention variants and the one-arm ablation on the out-of-genomics generality tasks or on the real enhancer-gene benchmark, report that result and pause before adding mechanisms or tuning.
4. No retuning of the extrusion parameterization after seeing test results on a new task without reporting the untuned result alongside.
